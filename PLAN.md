# Workspace — 3D office for Claude Code sessions

A realistic-looking (low-poly stylized for now) 3D office running in the browser. Each **room** is a
project, each **desk** in a room is a live **Claude Code session** running on the server, embodied by a
character sitting at a computer. The desk monitor shows the session's terminal, a status lamp shows its
state, and interacting with the desk gives full access to the session. Claude sessions in the same room
know about each other. A **master room** belongs to the user: a 2D map of the office, an inbox of
pending questions, a timeline, and a Haiku-powered summary of everything that is going on.

Idea backlog: [`IDEAS.md`](IDEAS.md). Conventions for contributors/agents: [`CLAUDE.md`](CLAUDE.md).

---

## 1. Decisions

| Topic | Decision |
|---|---|
| Server | Runs on this Mac during development; target is a Linux server. Everything must stay portable (no macOS-only APIs). |
| Sessions | Unlimited number of desks. Real interactive `claude` CLI in a PTY — the terminal the user sees is the genuine Claude Code TUI. |
| Billing | Claude subscription (OAuth of the `claude` CLI). No API key. Haiku runs through `claude -p --model haiku`. |
| Working copies | One git worktree + branch per desk by default; optional "shared folder" mode per desk. |
| Room/desk management | From the web UI (in-world + HUD panels). |
| Visual style | Low-poly stylized, warm lighting, lots of props. Realism later. Assets generated by us in Blender (scripted, reproducible). |
| Navigation | Both: "dollhouse" overview (orbit, click to fly to a room/desk) and first-person (WASD by physical key, pointer lock, collisions). |
| Haiku summary | Generated on login ("since your last visit") and on demand. |
| Security | Password login now (hashed, HTTP-only cookie session); 2FA later. |
| Persistence | Sessions survive server restarts (process host outside the Node server) and machine reboots (`claude --resume <session-id>`). |
| Language | All repository content in English. Web UI localized FR + EN (i18n, more languages later). |

## 2. Architecture overview

```
Browser (apps/web)                                   Server (apps/server, Node 24)
┌──────────────────────────────┐   HTTPS + WS   ┌────────────────────────────────────────────┐
│ React + React Three Fiber     │◄─────────────►│ Fastify: REST API, WebSocket hub, auth     │
│  - 3D office (rooms, desks)   │               │ RoomService / DeskService (SQLite)         │
│  - screen previews (canvas)   │               │ SessionHost ──► tmux / claude --bg ──► claude CLI (per desk)
│  - full xterm.js terminal     │               │ TerminalMirror (@xterm/headless per desk)  │
│  - HUD: inbox, map, timeline  │               │ HookIngest ◄── HTTP hooks (per desk token) │
│  - i18n (fr, en)              │               │ StateMachine → events → timeline (SQLite)  │
│  - WebAudio ambience          │               │ OfficeBus (room board, messages)           │
└──────────────────────────────┘               │ Summarizer ──► claude -p --model haiku     │
                                                └────────────────────────────────────────────┘
                                                      ▲                    ▲
                        office MCP (stdio, per desk) ─┘   `http` hooks ─────┘  (both configured per claude session)
```

### 2.1 Monorepo layout (pnpm workspaces, TypeScript strict everywhere)

```
apps/server/          Fastify server, session host, state machine, SQLite, summarizer
apps/web/             Vite + React + R3F client
packages/shared/      Protocol types (REST DTOs, WS messages), desk states, zod schemas
packages/office-mcp/  MCP server (stdio) started by each Claude session for room awareness
assets/blender/       Python scripts that generate every GLB (characters, props) + README
apps/web/public/      Exported GLBs, textures, sounds
data/                 (gitignored) SQLite DB, logs, per-desk runtime files
```

Data directory (configurable, default `~/.workspace`): database, generated per-desk settings/MCP
config files, worktrees (`~/.workspace/worktrees/<room>/<desk>`). User projects are never modified
except through `git worktree add` (branch `workspace/<desk-slug>`).

### 2.2 Session host (process lifetime)

Claude processes must not be children of the Node server, otherwise every server restart kills them.

- **SessionHost interface**: `create(desk)`, `attach(desk) → pty`, `stop(desk)`, `list()`, `isAlive(desk)`.
- **Decision (Phase 1 spike): tmux** (`tmux -L <socket>`, one session per desk, dedicated config: no
  status bar, no prefix, no key bindings, `remain-on-exit` to read exit codes). The native
  `claude --bg` alternative was rejected: it ignores `--session-id` (it manages ids itself) and runs
  under Claude Code's own background service, so we would not control the process lifecycle.
- The server attaches to the host through `node-pty` and keeps a **TerminalMirror** (`@xterm/headless`
  + serialize addon) per desk, so any client can get the current screen instantly.
- Each desk gets a fixed `--session-id <uuid>` stored in SQLite. After a reboot, the desk is relaunched
  with `claude --resume <uuid>`.

Launch command per desk (sketch):

```
claude --session-id <uuid> --name "<desk name>" \
  --settings <data>/desks/<id>/settings.json      # `http` hooks → server
  --mcp-config <data>/desks/<id>/mcp.json         # office MCP
  --append-system-prompt "<identity + room etiquette>" \
  [--model ...] [--permission-mode ...]
env: WORKSPACE_URL, WORKSPACE_DESK_ID, WORKSPACE_DESK_TOKEN
```

### 2.3 Desk states (status lamp)

| State | Lamp | Source |
|---|---|---|
| `starting` | white, slow blink | process spawned, no `SessionStart` yet |
| `idle` | green | `SessionStart`, `Stop` (turn finished, waiting for instructions) |
| `working` | blue, pulsing | `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `SubagentStart` |
| `question` | orange, blinking | `PermissionRequest`, `PreToolUse` on `AskUserQuestion`/`ExitPlanMode`, `Notification` (`permission_prompt`, `elicitation_dialog`) |
| `compacting` | purple | `PreCompact` → `PostCompact` |
| `limited` | yellow | `StopFailure` with `error_type: rate_limit`; cleared by `Notification` `quota_auto_resume_fired` or the next prompt |
| `error` | red | `StopFailure` (other error types), crash, non-zero exit |
| `offline` | off (grey) | `SessionEnd` / process stopped |

Hooks are declared as **`http` hooks** in the per-desk `--settings` file: Claude Code POSTs each payload
to `http://127.0.0.1:<port>/internal/hooks/<deskId>` with `Authorization: Bearer $WORKSPACE_DESK_TOKEN`
(`allowedEnvVars`), and the server's JSON response is used as the hook output (e.g. `additionalContext`).
No relay script needed — except for `SessionStart`, which Claude Code does not deliver to `http`
hooks (verified): it uses a `command` hook that pipes the payload to the same endpoint with `curl`.
`Stop` carries `last_assistant_message`, used for the "ends with a question" heuristic and for the
summarizer; `UserPromptSubmit` carries a generated `session_title` (shown as the desk's topic).

**Blockers**: a question (`AskUserQuestion`, `ExitPlanMode`) or a permission prompt stays pending
until its `PostToolUse`/`PostToolUseFailure`/`PermissionDenied` (matched by `tool_use_id`, or by tool
name + input for permission requests). While any blocker is pending, parallel tool activity keeps the
desk in `question`. A turn boundary (prompt, stop, session start/end) clears them.

The first launch in a new folder shows Claude Code's trust dialog before any hook fires: the server
detects it on the mirrored screen and shows the desk as `question`.

The exact hook → state mapping is pinned down in `apps/server/src/sessions/stateMachine.ts` with unit
tests over recorded hook payloads. Every transition is stored (`desk_events`) for the timeline.

### 2.4 Room awareness (Claude ↔ Claude)

1. **Identity**: `--append-system-prompt` tells each session who it is (desk name, room/project,
   branch/worktree) and how to cooperate (check the board, announce what you work on, don't touch
   files another desk claims).
2. **Passive context**: on `SessionStart` and `UserPromptSubmit`, the hook response returns
   `additionalContext` with the current **room board**: every colleague, state, current task, branch,
   and unread messages addressed to this desk.
3. **Active tools** — office MCP (`packages/office-mcp`), authenticated with the desk token:
   - `office_colleagues` — list desks in the room with state and current task
   - `office_set_task` — declare/update what I'm working on (shown on the whiteboard)
   - `office_send_message` — message a colleague (or the whole room)
   - `office_read_messages` — read my inbox
   - `office_board` — read the shared room board (notes, decisions)
   - `office_board_post` — pin a note/decision on the board
4. Messages received while working are also delivered through `PreToolUse`/`PostToolUse`
   `additionalContext`, so a busy session sees them without waiting for the next user prompt.
5. `TaskCreated`/`TaskCompleted` hooks feed each desk's todo list to the room board and whiteboard.

### 2.5 Terminal streaming

- WS channel per desk: `subscribe(deskId, mode)` where mode is `preview` or `interactive`.
- `interactive`: raw PTY output (after an initial serialized snapshot), keystrokes and resize from the
  client. One interactive client controls the size; the host keeps a sane default (e.g. 120×36).
- `preview`: throttled (≈2 fps) compact screen frames (text + color runs) for the 3D monitors — the
  client draws them on a canvas used as the monitor texture. Only desks near the camera are subscribed.

### 2.6 Web client

- **Stack**: Vite, React, TypeScript, `@react-three/fiber`, `@react-three/drei`,
  `@react-three/postprocessing`, zustand, `@xterm/xterm`, `react-i18next`.
- **World generation**: the floor plan is computed from the room list: a corridor, the master room at
  the entrance, project rooms along the corridor (size depends on desk count), glass walls toward the
  corridor so lamps are visible from outside, a lounge/kitchen area.
- **Props (lots)**: desks, chairs, monitors, keyboards, mugs, lamps, plants, bookshelves, filing
  cabinets, whiteboards, printer, coffee machine, water cooler, sofa, rugs, wall clock (real time),
  posters, windows with sky, ceiling lights, trash bins, cables, sticky notes… instanced when repeated.
- **Characters**: rigged low-poly humans with random variations (skin, hair, clothes), animations per
  state: idle sitting, typing, hand raised (question), stretching/drinking coffee (idle), head in hands
  (error), asleep (offline/limited).
- **Navigation**: overview camera (orbit, click room → fly in, click desk → focus) and first-person
  (pointer lock, `KeyboardEvent.code` so WASD works on AZERTY at the same physical keys, 2D grid
  collisions against walls/furniture). `E`/click on a desk → focus its screen → full terminal overlay.
- **Master room**: monitor 1 = 2D map (live colors, click to teleport), monitor 2 = Haiku summary,
  wall screen = timeline, desk tray = inbox (pending questions; answering opens that desk's terminal
  without walking there). The inbox and minimap also exist as HUD overlays anywhere.
- **Whiteboard** in each room, rendered from the room board (same data the agents see).
- **Sound**: WebAudio, positional — room tone/HVAC hum, keyboard typing near working desks (volume
  follows the number of working desks), chime on new question, footsteps in first-person, doors,
  coffee machine. First version synthesized procedurally, later replaced by CC0 recordings.
- **i18n**: `react-i18next`, `locales/{fr,en}/*.json`, language switcher, browser detection; text
  drawn on 3D textures goes through i18n too. The Haiku summary is requested in the UI language.

### 2.7 Summarizer (Haiku)

- Input digest built by the server: per room/desk state, recent prompts, last assistant messages
  (from `transcript_path` JSONL), tool activity, git diff stats of worktrees, pending questions, and
  what changed since the user's last visit.
- Runs `claude -p --model haiku --output-format json` with tools disabled, in the user's language.
- Triggered on login and by a "refresh" action; cached in SQLite with its timestamp.

### 2.8 Security

- Password set on first run (CLI `pnpm setup-password`), stored as scrypt hash.
- Session cookie: HTTP-only, `SameSite=Strict`, `Secure` when behind HTTPS; login rate limiting.
- WebSocket upgrade requires the session cookie. Hooks and the office MCP use per-desk random tokens.
- Binds to `127.0.0.1` by default; exposure through a reverse proxy / Tailscale is a deployment choice.

## 4. Risks & open points

- **Subscription limits**: many parallel sessions drain the usage windows fast → the `limited` state
  and (later) a usage gauge.
- **Hook coverage**: some states (free-text question at the end of a turn) are not signalled by hooks →
  heuristics first, Haiku classification later (see IDEAS.md).
- **Terminal rendering in 3D**: previews are approximations drawn on canvas; the real TUI is only in the
  interactive overlay.
- **Blender-generated characters**: quality depends on scripting; start simple and iterate.
